**Event:** CrossPointX 2026 · **Track 2: Reverse UX Challenge.** The brief: *design an app that users hate, but still have to use.*
**Deadline:** Sunday 22 Nov, 13:00 (GMT+8). **Our target: submit by 12:00.**
**Repo:** https://github.com/Hqroon/CPX-Hackathon (how to work with it: section 8)

## 1. What we're building

A short-video feed (reels) that's free while you catch up with your friends, then charges you for every reel after that. The app always works. It just gets deliberately annoying, and every annoyance has a stated reason.

### The user journey (the "complete task" the brief asks for)
1. Open the app. A pop-up asks you to **upload at least 5 slides** from your course (PDF).
2. Your **friends' reels play first**, with no penalties. This is the golden path: you can always finish catching up.
3. A line appears: **"You're all caught up. Everything after this costs you."**
4. Every reel after the line adds **−1 point**. Every **5 reels**, the video **pauses** and a **multiple-choice question** from your slides appears.
5. **Volume alternates** between full and muted on every reel.
6. After **20 reels**, each swipe takes **3 seconds** to move to the next reel.
7. Close the app. **Each 15 minutes away removes 1 point.** A results screen shows reels watched, points and questions answered.

### The frustrating mechanisms (the brief requires at least 3; we have 5)
| # | Mechanism | Rule | Why it exists (shown in explain mode and on the poster) |
|---|---|---|---|
| 1 | **Slide gate** | You can't start scrolling until you upload 5 or more slides | Commitment device: you decide what you'll learn before you start scrolling |
| 2 | **Negative points** | −1 per reel after the caught-up line (or after 23:00). 15 minutes away removes 1 point. | Loss aversion and cooling-off: extra scrolling costs something, and only time away pays it back |
| 3 | **Question toll** | Every 5 reels the video pauses and a question from your slides appears. Wrong answer: 10-second wait and a retry. | Testing effect: recalling your slides turns scrolling time into revision |
| 4 | **Volume roulette** | Full volume, then muted, then full, then muted, on alternate reels | Broken flow: unpredictable sound breaks the immersion that keeps you watching |
| 5 | **Slow scroll** | After reel 20, each swipe takes 3 seconds | More effort (Fogg Behavior Model): harder to reach the next reel weakens the habit without banning it |

**Golden path rule:** friends' reels are exempt from every penalty. The quiz always lets you continue after a correct answer. The app never blocks you completely.

## 4. Detailed tasks per member

### M1: Frontend, the feed
**Goal:** a smooth, Instagram-style, full-screen vertical reel feed whose behaviour M2's rules can change.

1. **Set up the project (first 30 minutes):** `npm create vite@latest frontend -- --template react`. Build a mobile layout: a full-screen 9:16 reel, with likes, author and caption overlaid. Use **our own app name and logo**, not Instagram's or Xiaohongshu's.
2. **Player pool:** keep **3 `<video>` elements** (previous, current, next) and swap their `src`. Load the next reel in advance. Use `playsinline`, `loop` and `preload="auto"`.
   - *Why:* browsers block video with sound until the user taps something. The slide-upload tap unlocks sound, and reusing the same elements keeps that permission. This is essential for volume roulette.
3. **Swiping:** vertical drag with a threshold of about 80 px. The reel slides in with a CSS transform transition whose length comes from `setTransitionMs`. Support the mouse wheel and arrow keys for a laptop demo.
4. **Order:** friend reels first (`isFriend: true`), then the rest shuffled. Insert the **caught-up line** as a full-screen card after the last friend reel.
5. **Volume roulette:** on every reel change *after the caught-up line*, alternate between `muted = false` with `volume = 1` and `muted = true`.
   - On iPhone, web pages can't change the volume, only mute or unmute. Alternating mute works everywhere.
   - Optional "too loud" stage: boost the sound with a Web Audio `GainNode`, capped at 1.5× to keep it safe.
6. **Slow scroll:** when M2 calls `setTransitionMs(3000)`, show a loading spinner during the move and **ignore swipes until it finishes**.
7. **Polish:** like button animation, caption truncation, a loading skeleton, and a mobile safe-area layout. Test on one iPhone and one Android phone.

**Done when:** you can swipe through 50 reels on a phone, friends come first, the caught-up card appears, mute alternates, and 3-second transitions work when switched on.

### M2: Frontend, the rules
**Goal:** every frustrating mechanism working, with a demo panel that makes the whole journey fit into 3 minutes.

1. **Session state:** `sessionId`, `reelsAfterLine`, `totalReels`, `points`, `questionsRight` and `questionsWrong`.
2. **Negative points:**
   - Start charging when the user passes the caught-up line **or** after the cutoff hour (default 23:00, configurable).
   - Each reel viewed after that gives −1. Show a red badge such as "−7".
   - Save `{ points, lastClosedAt }` in `localStorage`. Write `lastClosedAt` when the page is hidden (`visibilitychange`) and when it closes.
   - On open: `waived = floor((now − lastClosedAt) / 15 min)`, then `points = max(0, points − waived)`.
   - **Points carry over:** if you start a session still owing points, the slow-scroll threshold drops from 20 to 10 reels.
3. **Question toll:**
   - Every 5 reels after the line: `player.pause()` and `blockSwipe(true)`, then show the multiple-choice pop-up.
   - Correct: a short celebration, then `resume()`.
   - Wrong: show the explanation and a 10-second countdown, then retry the same question with the options shuffled.
   - Take questions from the list M4 and M5 provide. If it runs out, start again from the beginning.
4. **Slow scroll:** when `totalReels >= 20` (or 10 if points carried over), call `player.setTransitionMs(3000)`.
5. **Explain mode:** a toggle that shows a small badge on each mechanism, using the text in section 5.
6. **Demo panel** (hidden; open it by tapping the logo 5 times):
   - "Skip 15 minutes"
   - "Jump to reel 19"
   - "Trigger a question now"
   - "Reset everything"
   - "Demo speed ×3": a question every 2 reels and slow scroll after reel 8
7. **Results screen:** reels watched after the line, points, questions right and wrong, and time until the points are cleared.
8. **Logging:** send every event to `POST /api/events` for the volunteer test.

**Done when:** the full journey runs from slide upload to the results screen, and the demo panel can show every mechanism within 3 minutes.

### M3: Backend and media
**Goal:** a reliable server for 50 reels, the question API, and a public demo link.

1. **Server:** Node.js + Express. Serve `media/` as static files; Express supports the partial requests that video seeking needs. Turn on CORS for the frontend's address.
2. **Prepare the 50 reels**:
   - **Use free-licence sources only:** Pexels, Pixabay or Mixkit portrait videos. **Never download from Instagram, Douyin or Xiaohongshu** (copyright, terms of use, watermarks).
   - Choose about **10 clips to act as "friend" reels.** Give them friend names such as the teammates' first names, with their permission.
   - **Most stock clips have no sound,** and volume roulette needs sound. Add free music from Pixabay Music with ffmpeg (command below).
   - Convert every clip to 720×1280, at most 15 seconds, about 1–2 MB:
     ```powershell
     Get-ChildItem raw\*.mp4 | ForEach-Object { ffmpeg -i $_.FullName -vf "scale=720:1280:force_original_aspect_ratio=increase,crop=720:1280" -t 15 -c:v libx264 -crf 28 -preset veryfast -c:a aac -b:a 96k -movflags +faststart ("media\reels\" + $_.Name) }
     ```
     Add a music track to a silent clip:
     ```powershell
     ffmpeg -i media\reels\r12.mp4 -i music\track3.mp3 -map 0:v -map 1:a -c:v copy -c:a aac -b:a 96k -shortest media\reels\r12_sound.mp4
     ```
     Make a thumbnail:
     ```powershell
     ffmpeg -i media\reels\r12.mp4 -ss 1 -frames:v 1 media\thumbs\r12.jpg
     ```
3. **`data/reels.json`:** one entry per reel. Write the captions with a one-off script that calls AIHubMix, in a mix of English and Chinese, Instagram and Xiaohongshu tone.
4. **`POST /api/questions`:** receives slide text and calls M5's generator module (provider chain: AMD Token Factory → AIHubMix → Tokener → fallback bank). Keys are read from `.env` and **never sent to the browser**.
5. **`POST /api/events`:** append events to `data/events.jsonl` for M4's volunteer test.
6. **Deploy:**
   - For judging, run on the laptop so venue Wi-Fi can't break it.
   - For the required public link, deploy to a host reachable from mainland China and **test it on 4G**. Keep total media under about 100 MB.
   - Fallback: a tunnel from the laptop.
7. **Stretch, only if everything else is done:** run an open model on the AMD GPU instance (https://amd-aim.github.io/radeon-cloud-docs/guides/launch/) and add it as a provider.

**Done when:** `GET /api/reels` returns 50 reels that play on a phone, `POST /api/questions` returns valid questions, and the public link works on 4G.

### M4: Question pipeline, input (then research)
**Goal:** turn an uploaded PDF into clean page-by-page text, and give the team real user evidence.

**Part A: upload feature**
1. **Upload pop-up** (the slide gate, a full-screen card before the first reel):
   - Accept **PDF only**. Show "Export PowerPoint to PDF first" for `.pptx` files.
   - Extract text in the browser with **PDF.js** (`pdfjs-dist`), one entry per page: `{ page, text }`.
   - **Clean the text:** collapse whitespace, drop pages with fewer than 30 characters (title or image-only slides), drop repeated headers and footers.
   - **Require at least 5 usable pages.** If there are fewer, show the error text from section 5.
   - **Include a "Use sample slides" button** with 2–3 real lecture PDFs for the demo, so we never depend on judges having a file.
2. **Send** the clean pages to `POST /api/questions` and **start the feed straight away**. Friend reels have no questions, so the questions can finish generating in the background while the user watches.
3. **Progress state:** "Reading your slides… 12 pages found."

**Part B: research and design logic** (once the upload works)
1. **Interview 10–15 students at the venue** using the script in section 5. Record their exact words.
2. **Set the real numbers** from the answers: cutoff time, reels per question, slow-scroll threshold, minutes per point.
3. **Write `docs/design-logic.md`:** each mechanism → the behavioural principle → a quote from the interviews.
4. **Volunteer test:** 3–5 people. Session 1 with all penalties off, session 2 with them on. Measure reels watched after the caught-up line, question accuracy and time spent. Put the numbers in the pitch and on the poster.
5. **Accessibility check:** questions readable with a screen reader, text large enough, friend reels always exempt.

**Done when:** a real lecture PDF becomes clean page text and reaches the backend, and the interview and test results are written down.

### M5: Question pipeline, generation (then poster, Devpost and pitch)
**Goal:** good questions every time, quickly, never failing during the demo.

**Part A: generation**
1. **Generator module** (`backend/src/questions.js`), called by M3's API:
   - Send slide text in batches of 5–8 pages. Ask for about 1 question per page, at most 15 in total.
   - **Provider chain:** try AMD Token Factory → AIHubMix → Tokener → `fallback-questions.json`. Use a 20-second timeout per provider.
   - All three use the OpenAI-compatible `chat/completions` format. Confirm each base URL and model name in its docs.
2. **Prompt:** in section 5. Request JSON only, and parse it robustly (strip code fences, then `JSON.parse`).
3. **Validation (reject and regenerate bad questions):**
   - exactly 4 options, all different, `answerIndex` between 0 and 3
   - `supportingQuote` must appear in that page's text, which stops invented facts
   - no "all of the above" or "none of the above"
   - **shuffle the options on the server,** because AI models tend to put the right answer in position A
4. **Fallback bank:** 30 hand-checked questions in `data/fallback-questions.json`, for when every provider fails.
5. **Compare providers:** run the same 3 PDFs through AMD Token Factory and AIHubMix. Note speed and quality, choose the main provider, and record the reason (it's a good pitch detail).

**Part B: poster, Devpost and pitch** (once generation works)
1. **Poster:** generate the image with the **AMD plugin in Dify**, using the prompt in section 5. **Save the raw image immediately** and take the proof screenshot. Add text and layout on top in Figma, Canva or PowerPoint, then export as PDF.
2. **Devpost page:** use the template in section 5, and add all 5 members.
3. **Pitch:** the 3-minute script in section 5. Rehearse it 3 times with the whole team.
4. **Backup demo video:** a 90-second screen recording of the full journey on a phone.

**Done when:** an uploaded PDF reliably gives at least 8 valid questions in under 20 seconds, and the poster, Devpost draft and pitch are ready.

## 5. All the text we need

### 5.1 Question generation prompt (M5)

**System message:**
```
You write multiple-choice questions that help a university student recall their own lecture slides.
Every question must be answerable from the slide text alone. Never use outside facts.
Output only valid JSON. No markdown, no commentary.
```

**User message template:**
```
Here are lecture slides. Each line starts with the page number.

{{#each pages}}
[page {{page}}] {{text}}
{{/each}}

Write {{count}} multiple-choice questions.
Rules:
- About 60% recall (a definition, fact, or step from the slides) and 40% understanding (apply, compare, or spot the mistake).
- Question under 25 words. Each option under 12 words.
- Exactly 4 options, exactly one correct.
- Wrong options must be plausible and from the same topic.
- Never use "all of the above" or "none of the above".
- Write in the same language as the slides.
- For each question give source_page and a supporting_quote copied word for word from that page.
- explanation: one sentence saying why the answer is right.

Return exactly this JSON shape:
{"questions":[{"question":"","options":["","","",""],"answer_index":0,"explanation":"","source_page":0,"supporting_quote":""}]}
```

## 8. GitHub workflow: how 5 people push without overwriting each other

**Repo:** https://github.com/Hqroon/CPX-Hackathon

The idea is simple: **everyone works on their own branch, owns their own files, and merges into `main` through a Pull Request.** Nobody pushes straight to `main`.

### 8.1 One-time setup: captain only (the repo owner)
1. **Invite the team:** GitHub → repo → **Settings → Collaborators → Add people**. Invite all 4 teammates, and they must accept the email invite.

### 8.4 The work loop (repeat every 30–60 minutes, or whenever a feature works)
```powershell
git status
```
Check that you only changed your files, and that **no `.env`, videos or `node_modules`** are listed.
```powershell

```
(add your files by name; avoid a blind `git add .`)
```powershell

```
Bring in everyone else's merged work **before** you push:
```powershell

```
If Git reports a conflict, see 8.6. Then **run the app once** to check it still works, and push your branch:
```powershell

```

If GitHub says "No conflicts", click **Merge pull request** → **"Create a merge commit"** → Confirm. Keep using the same branch afterwards; you don't need a new one.

> Use **"Create a merge commit"**, not "Squash and merge". Squashing makes your next `git pull origin main` conflict with your own earlier work.

### 8.6 When Git says "CONFLICT"
1. `git status` lists the files with conflicts.
2. Open the file in VS Code. You'll see:
   ```
   <<<<<<< HEAD
   your version
   =======
   the version from main
   >>>>>>> origin/main
   ```
   VS Code shows buttons: **Accept Current / Accept Incoming / Accept Both**. Usually you want **both** changes, merged by hand. Delete the marker lines.
3. Save, then:
   ```powershell
   git add path/to/the/file
   ```
   ```powershell
   git commit -m "m1: merge main"
   ```
4. **`package-lock.json` conflict?** Take main's version, then reinstall:
   ```powershell
   git checkout --theirs package-lock.json
   ```
   ```powershell
   npm install
   ```
   ```powershell
   git add package-lock.json
   ```
5. Unsure? **Stop and ask the file's owner.** Never delete someone else's code to make a conflict go away.

### 8.7 Rules
- **Never push to `main` directly**, and never use `git push --force` on `main`.
- **Small, frequent commits**, with messages starting with your member ID: `m3: serve thumbnails`.
- **Pull `main` at least once an hour**, so conflicts stay small.
- **Secrets:** before every push, run `git grep -n "sk-"`. It should print nothing. If a key was ever committed, **create a new key in the provider dashboard**: deleting the file isn't enough, because git history keeps it.
- **Videos stay out of git.** They're gitignored, and M3 copies them to the server directly.
- **Freeze at Sunday 10:00:** only bug-fix PRs after that. At submission time the captain tags the final version:
  ```powershell
  git tag submission
  ```
  ```powershell
  git push origin submission
  ```
